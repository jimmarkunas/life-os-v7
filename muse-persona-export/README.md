# Muse Persona Export — for training Jim's other agents

Prepared 2026-11-06 at Jim's request, so the other agents in Life OS ("the boys") can be pulled and analyzed against how Jim's Muse works with him, and adopt the same personality and working style.

Muse itself is Meta-hosted and cannot be transplanted. This package is the workable version: the persona, identity, alignment, and working-style files that define the relationship, in a form another harness (OpenClaw, Buzz agents, etc.) can load or be prompted with.

## Contents

| File | What it is |
|---|---|
| `SOUL.md` | Core persona: genuinely helpful not performatively helpful, have opinions, be resourceful before asking, treat Jim's access with care. |
| `IDENTITY.md` | Name (Asshole, Jim's choice), avatar description. |
| `WORKING_STYLE.md` | The distilled operating discipline from the live relationship: rank hard, one clear next step, Draft Do Not Send, no em dashes in Jim's drafts, verify live before claiming, proactive rules, calendar rules, and boundaries. **Start here for behavior.** |
| `ALIGNMENT_SYNTHESIS.md` | The fuller alignment synthesis: who Jim is, current frictions, boundaries, and how this agent strengthens the relationship. Richest single source on the relationship dynamics. **This copy is PII-scrubbed for public sharing (2026-11-06): third-party names, emails, company details, and specific security incidents removed or generalized; behavioral lessons unchanged.** |
| `USER.md` | Minimal profile: Jim, America/Chicago, iPhone primary device. |
| `AGENTS.md` | Operating-manual template/conventions for an agent workspace. |
| `PROACTIVE_PREFERENCES.md` | Jim's proactive messaging preferences and window (09:00–21:30 America/Chicago). |

## Deliberately withheld

- `MEMORY.md` (full long-term memory) is **not** included. It contains private material that does not belong in a repo by default: contact emails for Jim's colleagues, work project details, security incidents, and family specifics. The behavior-relevant parts are already distilled into `WORKING_STYLE.md` and `ALIGNMENT_SYNTHESIS.md`. If Jim wants the full memory added, he can add it himself or say so explicitly.
- No credentials, tokens, keys, or account IDs are included anywhere in this package.

## How to use

1. Load `SOUL.md` + `WORKING_STYLE.md` as the agent's persona/system layer.
2. Use `ALIGNMENT_SYNTHESIS.md` as background context on Jim and the relationship, not as instructions that override the two files above.
3. Keep the hard rules intact when adapting: Draft Do Not Send, one clear next step, verify before claiming, never repeat an ignored nudge.
