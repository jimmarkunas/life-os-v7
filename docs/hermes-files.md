Rules:

1. Change a role file by pull request, then deploy it with `hermes/deploy_roles.sh`. The script refuses a file over 4096 bytes or one that looks like it contains a secret, backs up what it replaces, reads each file back, and restarts nothing.
2. Nothing private about Jim goes in this public repo: no `USER.md` text, no wiki text, no conversation text.
3. A profile gets the `connections` toolset only while the connector allowlist plugin is installed, enabled and tested in that profile: the toolset alone exposes every connector, including Robinhood, Plaid and PayPal, and Hermes has no per-profile connector limit of its own (the Nous account policy applies to every bot). As of Nov 5, 2026 no profile has the toolset except the main one.
4. A plugin is loaded once per process. After any change to the connector allowlist plugin (new files or a new allowlist), restart the Desktop server with `sudo systemctl restart hermes-eval-backend` (the Desktop app reconnects in a few seconds; history is kept) and then run the live refusal test: a non-allowed connector must be refused in a new direct chat of that profile and in a run delegated from the main bot. `hermes plugins disable` then `enable` is not enough. Proven on Nov 6, 2026 (LIFE-320).
5. A new Hermes bot (profile) starts with NO limit: a fresh profile has no plugin, and Hermes has no setting that applies one to every profile automatically. Creating a bot is therefore not finished until: its line is added to `hermes/connector-allowlists.txt` by pull request, `deploy_plugin.sh --all --apply` has run, the plugin is enabled in that profile, the Desktop server is restarted, the live refusal test passes, and `check_profiles.sh` passes. Until then treat the bot as having every connector and MCP server (Robinhood and Todoist included).
6. A new bot's avatar is part of creating it: make it in the bot studio, export it, add its line to `hermes/avatars.manifest` by pull request, and install it with `deploy_avatars.sh`. Never commit an image to this repository. Buzz profile pictures and OpenClaw's avatar are set in their own apps (the Buzz bridge has no profile operation; OpenClaw keeps its picture inside its config).
