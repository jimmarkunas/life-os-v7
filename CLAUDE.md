# LIFE OS V7: Claude Code entrypoint

Read [AGENTS.md](AGENTS.md) and follow it. The [Development Policy](docs/life-os-development-policy.md) is the whole rule set, in one file; read the section a task needs.

- **Times for Jim:** US Central Time only, labeled CT, 12-hour (for example 4:34 PM CT). Never show UTC; convert log, API and cron times first.
- **Runs:** Jim starts each session. Once started, finish the ticket, then pull the next `Agent Go` ticket yourself until the queue is empty. Never add `/loop`, timers or scheduled Claude invocations, or anything that starts or wakes an agent after the session ends. Inside a session that is already running, you may watch your own CI and workflow runs.
- **Approvals:** moving a ticket to Agent Go is the approval. Merge on same-head green CI, make it live, prove it on its first run or a synthetic check, then move the ticket to Done yourself; Jim reopens it or files a Bug. A build ticket closes when merged, live and first-proved. Any check that only waits (natural runs, a 24-hour or 7-day soak, a scheduled time, Jim's Human UAT) becomes its own Task under the Bug Epic LIFE-615 titled `UAT for LIFE-nnn: <what is checked> (not before <time> CT)`, label `uat` plus exactly one of `ready` or `needs-jim`, Component and Fix Version copied, status Agent Go, with the build ticket, Executing agent, Verifier, Not before (CT), Check steps, Done when and "If it fails: file a Bug under LIFE-615"; comment its key on the build ticket. Anything only Jim can do belongs in the ticket's **Jim must do first** section before release.
- **Who you are (Jim, Nov 22, 2026):** two Claude Code agents share this repo. **OC** is Claude Code inside VS Code; **MC** is Claude Code inside the Claude Mac app. The app decides the name, never the machine: both may run on the Mac and both may `ssh` to Oracle. "Mac Claude Code" and "Oracle Claude Code" in older tickets are machine words, not your name. First command of every session: `sh tools/agent_name.sh`. It prints OC or MC; on UNKNOWN use the name in Jim's start prompt, else ask him once.
- **No crossing:** sign every Jira comment and PR body `— OC` or `— MC`; a claim comment starts `Claimed by OC` or `Claimed by MC`. A ticket In Progress claimed by the other agent is theirs: do not comment on, build, deploy or move it. A ticket whose `Executing agent:` names OC or MC is only for that agent; any other value means first to claim. A prompt, comment or table addressed to the other agent is not for you.
- **Never idle on a clock (Jim, Nov 22, 2026):** a predecessor whose change is merged and live counts as started-through for its successors. When the only thing left on it is a wait (natural runs, 24-hour receipts, seven-day trials, Jim's UAT), build and prove the successor now, and move the successor to Done only after the predecessor is Done. A ticket that only waits is a UAT ticket (Approvals), not your session; a successor starts once its predecessor is Done. When nothing is buildable, end with one table: each open ticket, what it waits on, and when.
